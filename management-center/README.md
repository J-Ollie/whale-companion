# 小鲸鱼管理中心

独立的 Python 标准库网页服务，提供连接诊断、人工恢复入口、好友聊天、公开/私密日记、身份档案、记忆依据、模型余额和访客留言。功能、认证与边界详见 [模块说明](../docs/MODULES.md)。

## 入口与权限

服务默认只监听 `127.0.0.1:6190`。使用本地隧道或受信任的 HTTPS 反向代理访问；直接打开本地 HTML 不会建立后台连接或授权。

- 管理员首次在本地授权入口设置自己的 8—128 字符密码；没有预置密码。密码只保存 scrypt 哈希与随机盐。
- 业务 API 校验启动/代理凭据和登录会话，刷新页面或服务重启后可能需要重新登录。
- 访客入口仅提供允许公开的状态、档案和日记，不能读聊天、私人记忆、私密日记、留言收件箱或模型余额。
- 昵称自愿填写且未经身份验证，不能用它认定 QQ 身份。

## 诊断与恢复

分别检查 Docker、AstrBot、OneBot、QQ 登录与最近连通测试。QQ 显示在线仍需验证实际收发，长时间无人聊天不是故障证据。

恢复由管理员显式触发，最多重启接入一次，持久化冷却 10 分钟，不循环重登。SnowLuma 扫码和刷新在其 QQ 远程桌面完成；旧 NapCat 路径仍保留二维码兼容。网关、远程桌面和 AstrBot 必须另外部署。

## 数据与访客

- `recovery-data/` 保存密码哈希、访问凭据、诊断状态和来访数据库，不提交仓库。
- 从 AstrBot 私有目录受限读取聊天、日记、档案和记忆依据，不把完整数据库提供给访客。
- 来访按可信来源的加盐 IP 摘要合并 30 分钟，只记访问网站，不记录访问栏目；原始 IP 不落库。本地来源不明时回退匿名浏览器标识。
- 留言仅管理员和小鲸鱼可读，有限摘要导出到 `plugin_data/companion_visitors/feed.json`。
- `balance.py` 只查询配置中的官方 DeepSeek 账户余额；多个不同账户或配置无效时停止，不猜测选择。密钥不返回浏览器。

## 新部署与旧部署

本仓库将原 `qq-recovery/` 更名为 `management-center/`。服务示例使用 `/opt/qq-companion/management-center`；`qq-companion-recovery.service` 名称、`QQ_RECOVERY_*` 变量和私有数据目录保留兼容名称。

现有服务器可以继续原路径运行，整理公开仓库不要求移动生产目录。若主动迁移路径，先备份，更新 systemd 的 WorkingDirectory / ExecStart，并保留全部数据和凭据。

详细步骤及只读文件系统追加权限见 [部署说明](../docs/DEPLOYMENT.md)。前端引用的部分角色图片未附带，应自行提供有权使用的素材，见 [第三方说明](THIRD-PARTY-NOTICES.md)。

## 测试

在本目录执行 `python -m unittest discover -s . -p 'test_*.py' -q`，或从仓库根运行 `python tools/run_tests.py`。测试使用临时数据和模拟网关，不代替真实登录、手机或每种恢复情形的验收。
