# 记忆 v1.3：持久化、有效期与预算

更新：2026-10-25。实现位于 `astrbot-plugins/astrbot_plugin_companion_memory/`。

## 数据和恢复

SQLite独立保存原始观察、事实、引用依据、版本、忘记来源和整理进度。新建AstrBot对话、裁剪历史窗口及重启插件不清空这些数据。公开姓名与整体性格保存在公共档案并同步人格；不同联系人的私聊和事实按真实发送者隔离。

新窗口自动恢复有限核心与少量最近交流；更早内容通过回忆工具选择性读取，不注入全部聊天。提取排队及长消息分段有持久化游标，未整理内容可在之后处理。保存不等于保证每次完全召回。

## 类型、时间和证据

| 内容类型 | 用途 |
| --- | --- |
| semantic | 稳定知识、偏好及事实 |
| plan | 计划与约定，日期过去不推断已经完成 |
| state | 短时状态，避免长期当作现状 |
| working | 当前话题与未完讨论 |
| episode | 有来源的共同经历／对话片段 |
| impression | 暂时理解，不能当成事实或永久标签 |
| self_model | 有依据且可公开投影的成长 |

类型、有效期、来源、版本和可见范围分开。日期从原话时刻解析，未知不猜。印象／临时状态可到期待核对，历史条目保留。更正有版本；冲突先标待核对，手动固定条目不被自动覆盖，固定不会让日期永久有效。

事实引用须有用户原文支持，防止截掉否定、条件或主语。助手说过只证明说过，不能证明执行过。忘记同步清理索引与派生引用，保留管理员独立原始归档。

## 检索和整理

SQLite FTS5索引覆盖库内原文与条目，取消旧的最近2000条候选截断。用中文双字片段、关键词和固定同义词查找；无命中时最多一次短查询改写。不是向量模型或外部embedding服务，也没有训练记忆管理策略。

同主题引用形成带来源编号和指纹的关联集合，避免多轮摘要反过来成为自己的新证据。写条目、更新索引、整理游标同事务提交。检索工具不接受其他QQ、SQL或路径，固定当前验证联系人的范围。

## 当前实例预算

| 项目 | 上限 |
| --- | --- |
| 自动注入本人记忆 | 2600 UTF-8字节 |
| 共享公开简述 | 900字节 |
| 请求历史 | 7000字节／12条消息，完整用户轮与工具链 |
| 回忆工具 | 每事件4次，单次1800字节，合计4200字节 |
| 提取输入／输出 | 11000字节／900 tokens |
| 提取调用 | 同人至少600秒，合计每天48次 |
| 无命中查询改写 | 每事件1次、每天12次，输出160 tokens |
| 公共成长同步 | 来源变化时、至少900秒间隔，输出220 tokens |
| AstrBot历史／模型配置 | 12轮按轮裁剪，16384 tokens上下文，普通输出2048 |

模型／历史设置属于实例运行配置，**不会仅因安装插件自动全部生效**，需部署者自行配置。字节不是计费token；本轮输入、媒体、其他插件及固定提示另占空间。公开状态文案、日记和手机决策是不同调用来源。睡眠和休息不执行记忆整理，预算用尽延后处理，不丢游标。

## 文件索引

- `memory.py`：原始记录、事实、事务与遗忘。
- `lifecycle.py`：类型、时间、冲突与旁表迁移。
- `recall_index.py`：按联系人隔离的全文索引。
- `cognition.py`：有界注入、搜索、读取及关联引用。
- `reflection.py`：增量材料、长消息分段、游标。
- `budget.py`：字节预算、完整历史轮裁剪。
- `profile.py`：共享姓名、别名与公开性格。
- `main.py`：挂钩、工具、频率／每日上限。

管理中心显示类型、有效时间、冲突和依据，访客不能访问。全库只指已经保存的历史，不保证抓取完整QQ记录。未验证的原话与主观印象仍须标明性质。
