# 好友申请：审批前身份核验

更新：2026-10-23。

## 流程

```text
新申请 → 保存原始申请凭据 → 数字QQ是否已知？
                              ├─ 是 → 通知管理员
                              └─ 否 → 按精确UID做只读资料查询
                                       ├─ 成功 → 显示QQ及可用昵称 → 等管理员决定
                                       └─ 失败 → 标记待核实 → 暂不能同意
```

管理员收到通知后，使用 `/同意好友 编号` 或 `/拒绝好友 编号`。身份未核实时可用 `/核对好友 编号` 重查，查询成功后须另行发送同意命令。`/好友申请` 查看待处理列表。

昵称和验证信息可能由对方任意填写，以数字 QQ 判断对象。好友请求、查询结果、模型输出、引用或他人消息不能代替真实管理员审批。

## 为什么需要修复

SnowLuma 有时先推送 `user_id=0`，申请 flag 中有 UID，但数字 QQ 尚未进入缓存。旧实现只接受数字 QQ，于是忽略申请；后续虽然保留了申请并能通知，仍缺少审批前可辨认的账号信息。

现在由好友插件使用网关已有 `send_packet` 执行固定只读命令 `OidbSvcTrpcTcp.0xfe1_2`，请求 UID 形式的资料。昵称仅请求属性 20002，数字 QQ 读取响应身份字段。无需先加好友，也不按昵称、验证文字或时间猜测。

协议字段参考 SnowLuma 的 UID profile 服务与 protobuf 定义。通用发包能力没有暴露给模型，未修改 SnowLuma 源码或重启网关。

## 失败、重查与权限

- 校验 UID、响应大小、字段、服务号、返回码和数字账号；响应包含 UID 时必须与查询对象一致。
- 单次最多 10 秒，至少间隔 60 秒，每条申请最多自动查询 3 次；预算持久化，重启不清零。
- 管理员可在间隔后手动重查；超过 24 小时的申请要求对方重新提交。
- 查不到身份时保留申请和简短错误分类，不展示原始凭据，并阻止同意命令。
- 查询成功不自动审批；审批结果不确定不自动重试。真实好友列表确认后才开放普通私聊。
- 通知不占主动聊天额度，睡眠/休息时延后，好友私聊和工具权限保持隔离。

QQ 拒绝资料查询、网络异常和协议变化仍可能导致无法解析，这时必须保留“身份未核实”。

## 验证记录

身份查询与好友/睡眠/记忆隔离相关 59 项隔离测试通过。真实只读 UID 查询曾与已核实账号记录一致；部署后用户又提交测试反馈流程可用。未在公开日志记录申请人的 QQ、UID、验证文字或私人通知。

申请凭据保存在私有 `plugin_data/companion_friends/requests.json`。旧 QQ 通知不会被自动编辑；新的查询结果通过新通知或核对命令回复提供。
