# 开发与发布工具

## 测试

在带 AstrBot 和插件依赖的 Python 环境，从仓库根运行：

```bash
python tools/run_tests.py
node --check management-center/web/app.js
```

插件和管理中心分别启动解释器，避免同名测试文件及顶级导入冲突。不要把真实凭据或生产数据库作为测试输入。

## 白名单公开导出

`export_public.py` 供维护者把私有开发目录中的源码和测试同步到独立发布目录。调用时填写自己实例的实际标识；输出会替换为示例值。

```text
python tools/export_public.py --source <私有源码目录> --destination <公开仓库目录> --owner-qq <管理员QQ> --bot-qq <机器人QQ> --server-ip <服务器IP> --phone-ip <手机私网IP>
```

源目录与目标必须是相互独立的目录，不能互相嵌套。选中五个插件的源码/配置模板、管理中心 Python/网页和测试；运行配置、凭据、数据库、相册、日记、压缩包和第三方安装包不选取。

同时替换普通地址和正则表达式里转义的地址，检查常见凭据形状。输出 `docs/source-manifest.json`，记录被导出文件的 SHA-256。仓库的文档、服务模板和额外 systemd 配置独立维护，不由该脚本覆盖。

内容不变时保留原始文件字节，避免仅换行格式变化。明确虚构的测试Key可用等值拼接表达，不能因此关闭或放宽凭据检查。

脚本不执行 Git 提交或推送，也不自动删除旧文件。每次应人工审阅差异、检查敏感信息、运行测试，再分批提交；它不能保证识别所有私人信息。
